# Agent Harness Architecture: Console vs. Oh-My-Pi

This document details the core harness capabilities discovered in `oh-my-pi`, specifies our scoped **Role-Based Model Configuration** (`default`, `plan`, `vision`, and `smol`), and compares the broader agent harness design between `console` and `oh-my-pi`.

---

## 1. Core Model Roles Specification (Console Scope)

To balance power with simplicity, `console` will adopt a focused 4-role model system:

```ts
export type ConsoleModelRole = "default" | "plan" | "vision" | "smol";

export interface ModelRoleMapping {
  default: string; // Main conversational & execution model (e.g. anthropic/claude-3-7-sonnet)
  plan?: string;    // Architect model with deep reasoning / thinking (e.g. anthropic/claude-3-7-sonnet:high or openai/o3-mini)
  vision?: string;  // Multimodal model for image/UI inspection (e.g. google/gemini-2.5-pro or openai/gpt-4o)
  smol?: string;    // Fast, lightweight model for background tasks & summaries (e.g. google/gemini-2.5-flash or anthropic/claude-3-5-haiku)
}
```

### Role Routing Rules:
1. **`default`**:
   - The primary driver for daily coding, editing, and terminal commands.
2. **`plan`**:
   - Activated automatically when switching into **Plan Mode**.
   - Ensures architecture, planning, and task breakdowns are generated by a high-capacity reasoning model with elevated thinking levels, without requiring the user to manually switch their session model.
3. **`vision`**:
   - Invoked whenever prompts contain images, screenshots, or mockup inspection tasks.
   - If the `default` model is text-only or expensive, image analysis is routed to `@vision`.
4. **`smol`**:
   - Invoked for low-latency, high-frequency utility tasks:
     - Context compaction structural/LLM summaries.
     - Git commit message generation.
     - Fast file triage and subagent quick scans.

## 2. In-Depth Harness Comparison: Oh-My-Pi vs. Console

Beyond model roles, `oh-my-pi` includes several sophisticated harness capabilities:

| Harness Dimension | `oh-my-pi` | `console` (Current) | Target Enhancement for `console` |
| :--- | :--- | :--- | :--- |
| **Model Specialization** | 10+ roles (`plan`, `vision`, `smol`, `slow`, `commit`, `tiny`, `task`, `advisor`, etc.) + thinking levels (`:low`, `:high`). | Single active model per session; subagents inherit parent model. | Implement 4 focused roles: `default`, `plan`, `vision`, `smol`. |
| **Advisor / Watchdog** | Background reviewer agent (`WATCHDOG.yml`) that reviews transcript deltas in real-time, runs read-only checks, and injects advice without blocking. | None. | Future consideration for pair-programming verification. |
| **Storage Architecture** | Dual storage: content-addressed global **Blob Store** (`blob:sha256:...` for images/binaries) + session-local **Artifact Manager** (`artifact://` for big logs). | SQLite messages table + temp media storage. | Externalize large tool outputs from SQLite to artifact files to keep DB queries instant. |
| **Language Server Protocol (LSP)** | Built-in LSP multiplexer (`lspmux`) and client for TypeScript, Rust, Python, Go; queries diagnostics, go-to-definition, and symbols directly. | Regex grep / fd file search / terminal commands (`tsc`, `cargo check`). | Native LSP client for precise type errors and symbol navigation. |
| **Autonomous Long-Term Memory** | 5 backends (`local`, `mnemopi`, `hindsight`, `sharpshooter`, `off`); auto-learns rules (`learn` tool), captures lessons, and injects memory into system prompt. | Static `AGENTS.md` and custom rule files. | Ephemeral memory consolidation across sessions. |
| **Context Window Resilience** | Multi-tier maintenance (`shake` -> `snapcompact` -> `summarize` -> `handoff`), mid-turn safety checks, 400 overflow auto-recovery. | Post-turn threshold compaction (85% limit) with structural summary. | Implement tool output pruning (`shake`) and mid-turn threshold checks (see `docs/compaction.md`). |
| **Tool Execution Pipeline** | AST-based editing (`ast-edit`), structural search (`ast-grep`), interactive bash PTY with job control, and headless browser sessions. | Standard `read_file`, `replace_file_content`, `run_command` with background task tracking. | Integrate AST-aware edits and live terminal PTY streams. |

## 3. Implementation Plan for Console Model Roles

### Phase 1: Configuration Schema & Storage
- Add `modelRoles` to `settings.json`:
  ```json
  {
    "modelRoles": {
      "default": "anthropic/claude-3-7-sonnet",
      "plan": "anthropic/claude-3-7-sonnet:high",
      "vision": "google/gemini-2.5-flash",
      "smol": "google/gemini-2.5-flash"
    }
  }
  ```
- Store role configuration in server settings and expose via GET/POST endpoints.

### Phase 2: Runtime Role Resolver
- Create `apps/server/agent/src/service/role-resolver.ts`:
  - `resolveRoleModel(role: ConsoleModelRole): Model`
  - Fallback to `default` model if a specific role (`plan`, `vision`, or `smol`) is unconfigured.

### Phase 3: Integration with Agent Loop
- **Plan Mode**: When `session.mode === "plan"`, resolve and use `roleResolver.resolve("plan")`.
- **Compaction & Commits**: When running compaction summarization or git commit workflows, dispatch with `roleResolver.resolve("smol")`.
- **Image Prompts**: When user input contains images and the default model lacks vision capability, automatically switch the turn to `roleResolver.resolve("vision")`.
